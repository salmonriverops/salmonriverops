[See the full work and case studies](https://justinsmith.build/)

## What I build

- **Operating models for real businesses.** Connected models of customers, work, people, vehicles, equipment, qualifications, capacity, money, and exceptions. The work starts with making the unwritten rules explicit, so the business has a model it can own, inspect, and improve.
- **Systems that help people act.** The system surfaces conflicts, missing information, capacity limits, and decisions that require a person, with enough context to understand what needs attention and why.
- **Constrained AI with human approval.** Software and AI can read, check, and propose within defined rules. Decisions involving money, safety, compliance, employees, or customer relationships still stop for a person.
- **Judgment about what to change.** Some problems need AI, some need a connection between tools the business already pays for, some need a hard rule, and some need to be left with a good person. Deciding which is most of the work.
- **Tools built with the people who use them.** I work on site, learn the rules that are not written down, run the new system alongside the old one, and revise it until the team trusts it and uses it in the daily operation.

## Selected work

### Adventure Idaho operating platform

A live operating model connecting bookings, staffing, qualifications, vehicles, equipment, food, capacity, maintenance, collections, and daily changes. Weekly planning fell from 20 to 40 hours to roughly 2 to 4 hours.

[Operating platform](https://justinsmith.build/work/operating-platform/) · [Dispatch board](https://justinsmith.build/work/dispatch/) · [Communications layer](https://justinsmith.build/work/communications-layer/)

### Constraint discovery battery

A deterministic, human-in-the-loop tool that analyzes operational exports and proposes candidate business constraints for an operator to confirm or reject. Those candidates are a starting point for investigating the operation; the operator still has to establish the rules and exceptions the data does not capture. It runs locally with Python and DuckDB, and real business data never enters Git.

[View the repository](https://github.com/salmonriverops/constraint-battery)

### Personal OS

A private system for my own work and life. One press of a shortcut button on my phone captures a voice note. Clear, low-stakes items get filed on their own to the right task, list or project, and anything unclear or consequential comes back to me as a short question. Underneath is a real database with owner-only access, built with AI coding agents under the same discipline as work: request, test, approve, record. The point is removing friction: if capturing something takes more than a few seconds, it does not get captured. It is the same problem as the operation at a smaller scale, turning scattered context into a system that stays useful without handing consequential decisions to automation.

### What operators need from booking software

A living requirements spec, written from a high-volume multi-day operation: configuration written from the operator's own system, capacity that comes from that system, shared inventory across guided trips and rentals, and why written technical answers beat a demo.
